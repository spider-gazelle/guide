PgORM is a PostgreSQL ORM for Crystal. It extends [ActiveModel](../active_model/README.md) for attribute definitions, callbacks and validations, and adds persistence, associations, a query DSL, pagination and full-text search on top.

Because a model is an `ActiveModel::Model`, everything you already know about `attribute`, validations and `before_*`/`after_*` callbacks applies. This page covers what PgORM adds: connecting to the database, declaring a table-backed model, and persisting it.

## Installation

Add the shard, then require it.

```yaml
dependencies:
  pg-orm:
    github: spider-gazelle/pg-orm
```

```crystal
require "pg-orm"
```

## Connection

Configure the database once at boot. The simplest option is to parse a connection URL:

```crystal
PgORM::Database.parse(ENV["PG_DATABASE_URL"])
```

Or set individual values programmatically:

```crystal
PgORM::Database.configure do |settings|
  settings.host = "db.example.com"
  settings.port = 5432
  settings.db = "production"
  settings.user = "app_user"
  settings.password = "secret"
end
```

Every setting also reads from an environment variable by default: `PG_HOST`, `PG_PORT`, `PG_DB` (or `PG_DATABASE`), `PG_USER`, `PG_PASSWORD`, `PG_QUERY` and `PG_LOCK_TIMEOUT`.

!!! note "Read replicas"
    Call `PgORM::Database.parse_read(ENV["PG_DATABASE_READ_URL"]?)` to route standalone `SELECT`s (`find`, `where`, `count`, …) to a replica. Writes, and any read inside a `transaction` or `with_connection` block, always hit the primary, so you keep read-your-writes consistency. With no replica URL configured every query uses the primary.

## Declaring a model

Subclass `PgORM::Base` and declare attributes. The table name is inferred from the class name (`BlogPost` → `blog_post`), and an `Int64` primary key named `id` is generated for you.

```crystal
class User < PgORM::Base
  attribute name : String
  attribute email : String
  attribute age : Int32 = 0
end
```

### Table name

Override the inferred name with `table`:

```crystal
class User < PgORM::Base
  table "accounts"

  attribute name : String
end
```

### Primary key

Use `primary_key` to point at a different attribute, or pass several for a composite key:

```crystal
class Token < PgORM::Base
  primary_key :uuid
  attribute uuid : UUID
end

class Membership < PgORM::Base
  primary_key :user_id, :org_id
  attribute user_id : UUID
  attribute org_id : UUID
end
```

To change the default for a hierarchy of models, declare it once on a base class with `default_primary_key(name, autogenerated = true, converter = nil)`.

### Timestamps

Include `PgORM::Timestamps` to get `created_at` and `updated_at` columns. `created_at` is set on create, `updated_at` on every save; both are UTC.

```crystal
class User < PgORM::Base
  include PgORM::Timestamps

  attribute name : String
end
```

### Column types

Attribute types map to Postgres columns automatically — `String` to `TEXT`, `Int32` to `INTEGER`, `Time` to `TIMESTAMPTZ`, `UUID` to `UUID`, `Array(T)` to an array column, `Enum` to `INTEGER`, and any `JSON::Serializable` (or custom type) to `JSONB`. Make a column nullable by giving the attribute a nilable type (`String?`).

## Persistence

Build an instance and `save`, or `create` in one step. `save`/`create` return the record (check `persisted?`); the `!` variants raise `PgORM::Error::RecordInvalid` when validation fails.

```crystal
user = User.new(name: "John", email: "john@example.com")
user.save            # => true / false
user.persisted?      # => true

User.create(name: "Jane", email: "jane@example.com")
User.create!(name: "Alice", email: "alice@example.com")
```

Update by assigning attributes, or with the `update` helpers. `save!` only writes the columns that actually changed (dirty tracking).

```crystal
user.name = "Johnny"
user.save

user.update(email: "johnny@example.com")   # assign + save
user.update!(age: 30)

# skip validations and callbacks, straight UPDATE:
user.update_fields(last_login: Time.utc)
```

Delete a record with `destroy` (runs callbacks, handles dependent associations, wrapped in a transaction) or `delete` (a bare `DELETE`, no callbacks).

```crystal
user.destroy
user.destroyed?  # => true
user.persisted?  # => false
```

### Finding records

```crystal
User.find(1)                      # raises RecordNotFound if absent
User.find?(1)                     # => User?
User.find_by(email: "j@ex.com")   # raises if absent
User.find_by?(name: "John")       # => User?
User.first
User.last
User.all
```

`find`/`find?` accept a tuple when the model has a composite primary key.
